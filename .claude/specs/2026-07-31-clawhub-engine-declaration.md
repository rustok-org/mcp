> Статус: **ПЛАН, до `/check`.** Кода нет. Соло-режим (Капитан снял команду Инженер/Ревьюер
> на этой точке бэклога).
> Триггер: бэклог `.claude/reports/2026-07-30-agent-edition-audit.md`, Ф-4 («движко-нейтральные

## Находки разведки (проверено, не предположение)

1. **`skills/rustok-wallet/SKILL.md` frontmatter:** `metadata.openclaw.requires.bins: [docker]`.
   Это не текст — это поле, которое **ClawHub-установщик может использовать как гейт** перед
   тем, как вообще предложить скилл. Схема ClawHub поддерживает `anyBins` (OR-список) — это уже
   было подтверждено командой раньше (`.claude/specs/2026-07-11-tui-listing-skill-honesty.md`,
   строка про `requires.env/bins/anyBins/config`), но тогда `bins: [docker]` был честным, потому
   что podman-путь ещё не был задокументирован нигде. Сегодня это уже неправда: podman —
   доказанный рабочий путь (Ф-2/Ф-3), а поле всё ещё говорит «нужен только docker».
2. **`smithery.yaml`:** `commandFunction` жёстко возвращает `command: 'docker'`. Это не
   пример в комментарии — это код, который Smithery реально исполняет как локальный процесс
   на машине пользователя (архитектурное рассуждение: self-custody требует, чтобы ключи не
   покидали машину юзера — значит stdio-команда обязана выполняться там же, где обычно
   исполняется MCP-клиент, а не в облаке Smithery; официальная страница
   `smithery.ai/docs/build/project-config/smithery-yaml`, на которую ссылается сам файл, отдаёт
   404 — де-факто не проверить документацией, только архитектурой продукта). Хардкод реален как
   проблема для podman-only машины, не абстракция.
3. **Консольная линия (main) несёт те же два дефекта** (`requires.bins:[docker]`,
   `smithery.yaml` тоже `command:'docker'`) — не референс для решения, сама не починена.
4. **Найдено, но НЕ в этот круг:** `tests/test_claw_manifest.py` существует на консольной линии,
   но не на агентской. Один из его тестов (`test_claw_manifest_version_matches_pyproject`)
   **сломался бы немедленно** при прямом переносе — на агентской линии версии скилла и пакета
   **намеренно независимы** (0.4.6 skill vs 0.4.2 package, установлено Ф-2/Ф-3). Порт требует
   адаптации этого конкретного теста, это отдельная, самостоятельная задача — не входит сюда.

## Цель

Обе машинно-проверяемые точки перестают молчаливо требовать именно `docker`, честно отражая
сегодняшнюю реальность (docker ИЛИ podman), без рантайм-автодетекции (её нет и не требуется).

## Скоуп — входит

1. **`skills/rustok-wallet/SKILL.md`** (только frontmatter):
   `requires: bins: [docker]` → `requires: anyBins: [docker, podman]` (убрать `bins` целиком —
   не держать оба поля одновременно, это неоднозначность схемы). Версия `0.4.6` → `0.4.7`
   (ClawHub монотонна, следующий номер).
2. **`skills/rustok-wallet/claw.json`**: только `version` → `0.4.7` (frontmatter/claw.json версии
   синхронны по конвенции этой линии — сверено текущим состоянием, обе сейчас 0.4.6).
3. **`smithery.yaml`**: добавить конфиг-поле `ENGINE` (строка, необязательное, дефолт `"docker"`,
   описание — «docker or podman, whichever Smithery should invoke locally»); `commandFunction`
   использует `config.ENGINE || 'docker'` вместо литерала; header-comment — сноска, что
   `ENGINE=podman` меняет вызываемый бинарь (пример onboarding в комментарии остаётся на
   docker — не трогаем, он для человека, не для машины).

## Скоуп — ЯВНО не входит

- Полный шим `rustok` для агентской линии — опциональная часть исходного Ф-4, отдельное
  архитектурное решение (Капитан отдельно).
- Порт `tests/test_claw_manifest.py` с консольной линии — сломается на
  version-equality-ассерте по дизайну этой линии; отдельная задача (адаптация теста, не прямой
  порт) — кандидат в Ф-5/Ф-10, не сюда.
- Починка тех же двух дефектов на консольной линии (`rustok-wallet-tui`) — не в скоупе
  агентского аудита, свой отдельный круг, если Капитан решит.
- `INSTALL.md`/`TROUBLESHOOTING.md`/лендинг/`CONFIGURATION.md` — уже покрыты (проверено:
  podman упоминается 8/4/5/2 раз соответственно, бок о бок с docker), правок по существу не
  требуется.

## Затронутые файлы

## Решения (предрешены)

1. **`anyBins`, не оставить `bins` рядом** — одно поле, без двусмысленности; схема ClawHub уже
   подтверждена поддерживающей `anyBins` записью от 2026-07-11.
2. **`ENGINE`-конфиг в smithery, не рантайм-автодетект** — `commandFunction` это чистая функция
   `config → команда`, без доступа к файловой системе/PATH пользователя на этапе вызова;
   конфиг-поле — тот же паттерн, что уже есть (`KEYRING_PASS_PATH`), минимальный риск.
3. **Дефолт `ENGINE="docker"`** — обратная совместимость: существующие Smithery-конфигурации без
   явного `ENGINE` продолжают работать как раньше, ничего не меняется молча.
4. **Консольную линию не трогаем** — вне скоупа агентского аудита; заметить отдельно.
